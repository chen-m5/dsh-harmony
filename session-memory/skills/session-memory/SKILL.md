# 跨会话记忆怎么用（写给我自己看的）

工具是 `mcp__session_memory__session_search` / `session_recall` / `session_list`。
**能力不用背**（每次请求的 schema 里都有）；这份只记**纪律** —— 它决定我的回答是"查出来的"还是"编出来的"。

服务本体、架构、性能数字、重建步骤：`/storage/Users/currentUser/Documents/mcp-service/session-memory/README.md`

## 一、什么时候必须查

**必查**（都指向"会话之外的事实"）：

- 用户说「上次 / 之前 / 继续 / 那个 / 还是按老规矩」—— 指的一定不在当前上下文里
- 问项目既有约定、规范、踩过的坑（"这个项目怎么做 X"、"之前为什么这么定"）
- **我准备说"我记得 / 应该是 / 一般来说"时** —— 停，先查；查不到就直说没查到
- 用户指出我记错了，或我怀疑上下文里的信息过期时

**不必查**（别浪费一次调用）：

- 当前上下文里已经有的（刚读过的文件、刚跑过的命令）
- 纯推理、写代码、算数这类不依赖历史的事
- 只是想"再确认一下"但当前上下文已经足够确定

## 二、怎么读结果才不会被误导

1. **先看「范围：…」那一行**，它有三种形态：
   - `范围：当前工作区 <workspace>（要跨项目检索加 scope=global）` → 只搜了本项目，"没有"只代表**本项目**没有
   - `范围：当前工作区没命中，已自动扩大到全局` → 已经跨项目搜过了
   - `范围：全局`

   所以：要下"历史上没这件事"的结论之前，先确认范围已覆盖全局（必要时显式 `scope=global` 再查一次）。

2. **`⚠ 已放宽为「任一关键词匹配」` = 这不是精确命中**。它只说明出现过其中某个词，别当成"全部关键词都在场"的证据。

3. **片段只是线索，不是结论**。命中给的是 会话 id + seq + 片段（`片段在第 X/Y 字符` 告诉你它是从哪儿截的）。
   要下结论、要引用、要告诉用户"当时是这么说的"之前，用 `session_recall(sessionId, seq)` 读原文 ——
   它会附上「这一轮的用户消息 / 其后的助手回复」，帮我确认那句话是在什么语境下说的。

4. **引用历史时带上会话 id + seq**（"在 session-xxx 的 seq 1234"）。用户能复核，我错了也能立刻定位。

5. **查不到就换法**：多词 AND 无果 → 减词或换同义词（中文按字匹配，词序影响结果）；
   还不行就 `session_list` 看最近会话，再用项目名当 `cwd` 缩小；跨项目问题直接 `scope=global`。

## 三、"搜不到" ≠ "没发生"

库里只有 dsh 会话日志的 4 类事件（用户消息、助手消息、工具调用、工具结果），并且：

- **不入库**：注入的运行时上下文、reminder/命令块、只读命令本身（`ls`/`cat`/`grep`… 的结果在，命令记录不在）、短于 24 字符的工具结果
- **被截断**：单条上限 user 8K / assistant 12K / 工具结果 16K 字符 —— 超长输出的后半段查不到
- **只覆盖**：这台机器上的 dsh 会话；别的工具（IDE、浏览器、其它 agent）做的、别的机器上的事，一概没有
- **最多 60 秒延迟**：距上次同步超时才会先增量同步（约 0.5s），刚说完的内容可能还没入库

结论：搜不到只代表"库里没有"。该说"我没查到"，不要顺势编一个听起来合理的解释。

## 四、我该为将来留下什么

不用手动"写记忆"—— 每轮对话会自动入库（用户消息、我的回复、工具活动）。
真正要做的是：**把关键结论说清楚、把决定和理由讲明白**（"为什么选 A 不选 B"、"这个坑是怎么踩的"）。
将来（别的会话里的）我要靠这些文本回查 —— 含糊的一句话，等于没记。

同理：**发现并修掉的问题，把"症状 / 根因 / 判据 / 回滚"写进回复**，比只写"已修复"有用得多。
