# 打包说明 — 0.2.0-rc.2

> **给沙箱里的 agent 用**：把这一版的 dsh 打出来、部署到设备的运行目录、清掉中间产物。
> 只涉及 dsh 侧，不涉及壳。

## 这一版是什么

| 项 | 值 |
|---|---|
| 上游版本 | `@deepseek-ai/dsh@0.2.0-rc.2` |
| 目标平台 | openharmony-arm64（HarmonyOS 设备）|
| 改造内容 | 见 [`0.2.0-rc.2/CHANGES.md`](0.2.0-rc.2/CHANGES.md)：**13 个整文件替换** + 图片后端（jimp）+ 2 个 OHOS 原生包 + 顶层 `bin/` + pty 原生模块 |
| 本次升级要点 | 13 项里 **11 项官方内容逐字节未变**（直接复用上一版 `files/`），**2 项**（`dsh-client-ui-conversation`、`dsh-client-ui-settings-account`）按新版官方内容**重放**；4 类资产**零改动**（原生依赖版本全未变） |
| 产物 | `dsh-ohos-0.2.0-rc.2.zip`（**顶层目录必须是 `dsh-ohos-0.2.0-rc.2`**），约 **65 MiB** / 25229 条目 |

## 一、打包

```sh
# 在本仓库根
node scripts/fetch-dsh.mjs 0.2.0-rc.2                        # 拉官方树（有 pnpm-lock.yaml，约 16 秒）
node scripts/build-dsh.mjs 0.2.0-rc.2 --out <输出路径>/dsh-ohos-0.2.0-rc.2.zip
```

流程自动做六步并自检：复制官方树 → 校验 manifest 里记的官方 sha256 → 替换改造文件 →
装图片后端 → 拷 OHOS 原生包 → 装 pty 原生模块 → 放 `bin/` → 生成 `bin/` 别名 → 打包 → 校验产物。

**改过 `files/` 之后**先 `--refresh-sha` 刷新 manifest 的 sha256（否则第 2 步会报「与 manifest 记录不符」）：

```sh
node scripts/build-dsh.mjs 0.2.0-rc.2 --refresh-sha
```

首次或 `--clean` 之后会自动 `fetch`（有 lock，约 16 秒）。

## 二、解压到沙箱里的运行目录

目标目录固定为 `files/dsh-pkg/`（运行中的 dsh 就从这儿加载；与用户目录 `files/dsh-home` 对称）：

```sh
S=/data/storage/el2/base/haps/entry/files
rm -rf "$S/dsh-pkg" "$S/.pkg-stage"
mkdir -p "$S/.pkg-stage"
unzip -q <zip 路径> -d "$S/.pkg-stage"          # 解出唯一顶层目录 dsh-ohos-0.2.0-rc.2/
mv "$S/.pkg-stage"/* "$S/dsh-pkg"               # 顶层目录当包根搬到固定目录（壳的 PkgMgr 也这么做）
rmdir "$S/.pkg-stage"
ls "$S/dsh-pkg" | head
ls "$S/dsh-pkg/node_modules/@deepseek-ai/dsh/lib/bin.js"
```

> 落地目录**固定** `dsh-pkg`，不随版本变；zip 顶层目录名（`dsh-ohos-<版本>`）只是解包中间物 ——
> 壳按「唯一顶层目录」取包根，**不按目录名识别版本**。
> ⚠ 覆盖 `dsh-pkg` 会**打断正在运行的实例**，要换包请连壳一起重启。

## 三、清理打包痕迹

```sh
node scripts/build-dsh.mjs 0.2.0-rc.2 --clean     # 清 work/<版本>/ 与 work/.build-<版本>/（约 1.2 GB）
ls *.zip 2>/dev/null || echo "  仓库根无残留 zip"
```

## 四、验证（不碰正在运行的实例）

起一个**临时实例**（独立包目录 + 干净 `DSH_HOME` + 换端口）：

```sh
S=/data/storage/el2/base/haps/entry/files
T=$S/tmp/verify-020
rm -rf "$T"; mkdir -p "$T"; unzip -q <zip> -d "$T"
mv "$T/dsh-ohos-0.2.0-rc.2" "$T/pkg"; mkdir -p "$T/home"

cd "$T" && HOME=$S DSH_HOME=$T/home TMPDIR=$S/cache DSH_PERMISSION_MODE=danger-full-access \
  node --expose-internals "$T/pkg/node_modules/@deepseek-ai/dsh/lib/bin.js" web --no-open --port 32101
```

判断标准（0.2.0-rc.2 本次实测就是这些）：

| 检查 | 期望 |
|---|---|
| 日志 | 出现 `dsh web: http://127.0.0.1:32101/?token=…`，无 `plugin tree failed to load` |
| HTTP | 无 token **401** / 带 token **303** / 带 cookie 访问 `/` **200** |
| 最小任务 | 复制运行实例的 `.credentials.yaml` + `llm-deepseek/` 到临时 home，跑 `--profile headless "1+1"` → `2` |
| 能力抽查 | `flock` 真加锁（`tryLockExclusive(fd)`，懒加载必须真调用）、rg shim、jimp 闭包、`node-pty` 加载 |
| 写盘 | 让 agent 用 `write` 工具往 `/storage/Users/...` 写文件（验硬链接降级） |

验证完**停掉进程、删临时目录**（含临时 home）。

**千万不要**用正在服务的实例（默认 32100）做验证 —— 会打断用户会话。

## 五、坑（照做能省时间）

| 现象 | 原因 / 解法 |
|---|---|
| `✗ files/… 与 manifest 记录的 sha256 不符` | 改了 `files/` 却没同步 `manifest.json` → 跑 `--refresh-sha`（这是防上游漂移的闸门，别绕过）|
| 重放改动时锚点匹配不上 | 上游改了缩进/结构（0.2.0 的 `ui-settings-account` 那块 JSX 整体多缩了一层）→ 用 `diff -u work/<旧版本>/<文件> <旧版本>/files/<文件>` 先看清我们的改动，再在新版定位落点 |
| 打包后起不来 | 上游会**用同一版本号重发**包；按 sha256 比对，把差异文件覆盖进 `files/` 并在 manifest 里记 `reason` |
| grep/glob 报 `ripgrep launch failed` | `native/` 的 rg 是 **shim**，只覆盖 dsh 实际 argv；升级时核对 `dsh-tool-fs-search` 的调用参数（0.2.0 实测未变）|
| 图片功能全废 | `image-backend/` 没进包（懒加载，症状很晚才暴露）|
| `--clean` 后直接 build 报缺官方树 | 脚本会自动 fetch；失败就检查 `PNPM_CMD` 与网络 |
